# Changelog

## 0.3.1 — 2026-10-12 (the detached seat's Home Assistant)
- **Connect mode is a full first-class citizen**: a seat running elsewhere (the operator's own detached seat) gets the same HA access the inside child has — the same state push (`ha_entity` mirrors), and the token **delivered instead of inherited**: at every HA start the integration mints a fresh token and POSTs it to `POST /membrane/ha/token` on the seat's serve; the seat files it in `~/.config/membrane/hass.env` (0600) and reads it on its next turn, so an HA restart reaches the seat without a seat restart. An option (`ha_base_url`) says which Home Assistant address the seat should use when HA's own `internal_url` answer doesn't fit.
- **Restarts are announced across the wire**: the integration posts `ha-start` when Home Assistant is up and `ha-stop` on the way down to `POST /membrane/seat/event` (`restarts.py` notices) — a detached seat never reads an HA restart as the world going quiet.
- From the docker rehearsal: a bus listener that is a plain sync callable runs in HA's executor thread — ha-stop posts by hand from whatever thread it lands in (`seat_event_sync`), ha-start is an async listener on the loop.
- The boat's deploy script stages all three components (`membrane` patched at staging time so connect mode needs no PyPI package yet); docs: "connect mode = your own detached seat".

## 0.3.0 — 2026-10-12 (standalone + Home Assistant)
- **Standalone mode** (`membrane standalone`): the seat serves its own web UI — membrane home (the field in 3D following you), the chat on glass, voice — and opens it in the browser. No login on the local network (private, loopback, tailnet); a public or proxied caller is refused, never prompted. The person's name is typed once in the page. See docs/standalone.md.
- **Membrane in Home Assistant** (HACS, `custom_components/membrane`): a setup form (run the seat inside HA — HA's own Ollama integration used when there is one — or connect to a seat elsewhere; models picked from the server's list, changeable in the options); the seat as HA's supervised child process (loopback only, its environment chosen not inherited, data under `<config>/membrane`); the boat's UI takeover (membrane home as the landing page, HA's sidebar folded, ☰ to HA's pages); the Assist conversation agent and the field's sensors (merged from the boat's membrane_ai); the seat may use HA through a hidden non-admin system user, and HA pushes the states of the entities it mirrors (`ha_entity`) into its field. See docs/home-assistant.md.
- **The name ceremony**: a new seat is Bob ("Hey Bob") and asks its operator for a name; an agreed name is adopted only when the speech recognizer can hear it; the UI's labels and wake words follow it.
- **Voice**: in-browser transcription where the host has no speech server; the big speech models fetched on first use from the release, SHA-256 checked; the page's voice log goes to the seat (standalone).
- **The field viewer** grows with the field (a page opened on a young field re-projects as entities are born); the tab icon is membrane home's turning cube.
- **Packaging**: PyPI name `membrane-seat` (import and CLI stay `membrane`), couchbase and zeroconf optional extras, MIT LICENSE; the updater covers PyPI installs.
- **New seats report bugs and ideas** as GitHub issues the operator files (a prefilled link; the seat never posts).
- Fixes from the first strangers' seats: the dreamer crashed on every vote on a fresh seat; peer tools offered where no peers can exist (a goal waited forever); a nameless tool call from the backend (`no_name_1`) retried 14 times; the seat exited at boot on a dead TUI's pid file; the single-instance lock never bit on Alpine; a dead backend held the boot for minutes; panels created before their code loaded never booted (HA's panel loader).

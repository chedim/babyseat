RUN CODE: exec(action='run', code='ls -la ..') -- the code becomes a tree of entities in the field (one per node, shared wherever the same code appears) and its root is linked to its language's executor (sh: tool:executor; js, lang='js': presence, an opted-in browser tab): -execute-> owed, -executing-> running, -result-> a result entity for that run; you get rc + output, the root and the result. Re-run: exec(action='run', node=<root>). entity(action='read') on a root shows its code, state and runs. PROGRAM THE FIELD FIRST: what you will do again is a method -- define it on the entity it belongs to (or its class), then call it: exec(action='define', on='ha light', method='turn_on', command='curl ... {{self.entity_id}} {{level}}'), then exec(action='call', object='ha:light.port_strip', method='turn_on', args={'level': 40}) -- it returns rc + output (dash shell on this seat: use '.' not 'source'); or write a property whose write is the effect (help('cliffhanger')). A run's SHAPE (its tree with the paths, numbers, strings and expansions as holes) runs at most 3 times as a one-shot; the 4th is refused with the earlier roots: define it as a method then. A call straight at the executor (tool:executor, remote_executor, an implementation's exec) is refused. COMPOSITION: steps=[...] on a define, or entity(action='inherit', spec=<method>, parents=[...]) -- the parents run first and feed {{parent.head}} / {{parent.tail}}; a failed step halts. entity(action='read') on a method shows its last run (rc/head/tail). Your methods ride your context ('your methods: ...').

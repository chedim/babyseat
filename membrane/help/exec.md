RUN CODE: exec(action='run', code='ls -la ..') -- the code becomes a tree of entities in the field (one per node, shared wherever the same code appears) and its root is linked to its language's executor (sh: tool:executor; js, lang='js': presence, an opted-in browser tab): -execute-> owed, -executing-> running, -result-> a result entity for that run; you get rc + output, the root and the result. Re-run: exec(action='run', node=<root>). entity(action='read') on a root shows its code, state and runs. PROGRAM THE FIELD FIRST: what you will do again is a `Command:<name>` entity (its `cmd`; its varying values as "$1", "$2"), run by writing Command:<name>.run = {id, args: [...]} -- the receipt (rc, output) lands on the entity (help('stdlib')); or write a property whose write is the effect (help('cliffhanger')). A run's SHAPE (its tree with the paths, numbers, strings and expansions as holes) runs at most 3 times as a one-shot; the 4th is refused with the earlier roots: make it a Command then. A call straight at the executor (tool:executor, remote_executor, an implementation's exec) is refused.
